# Movie & Show Management System — Implementation and Design Plan

## Scope and execution context

Build the approved replacement from scratch in the newly initialized Manus WebDev project. The existing Figma URL returned HTTP 403 during this session, so its frames could not be inspected; apply the detailed supplied brief as the design source and do not claim Figma fidelity. The managed preview is configured for port 3000. The requested local developer workflow will expose Vite on 5173 and Express on 5000, with MongoDB at `mongodb://127.0.0.1:27017/...` configurable through environment variables. ## Implementation approach

Use a root npm-workspace package manifest with a pinned npm package-manager version, frontend in `frontend/`, and Express API in `backend/`. Keep common catalogue, schedule validation, seeds and status derivation reusable within backend modules and seed client-visible examples from API responses when the database is connected. Root scripts coordinate local development with one `npm run dev`, running Vite on 5173 and Express on 5000. A preview-compatible listener will honor the platform's `PORT` (3000) and serve the frontend while exposing the API under relative `/api` paths; configure the preview runtime/API route only through documented WebDev configuration. Do not hard-code the internal Preview origin.

MongoDB models cover User, Movie/Show, Theatre, Screen, Screening, Submission and maintenance/schedule availability as appropriate. The backend provides JWT sign-in/up, bcrypt password hashing, input validation, a secure environment-held JWT secret, and server-enforced `user` and `admin` roles only. Public registration creates only `user` accounts; the initial Administrator is provisioned securely by the explicit seed command. Catalogue CRUD, submission review, theatre/screen inventory, schedule production and operational reports are Administrator-only; users manage only their own watchlist/favourites. Include API health and informative Mongo connection errors. Do not present an in-memory fallback as persistence; label it demo mode and avoid silently accepting writes as saved.

The React application uses Vite, React Router, Tailwind CSS, Lucide React, reusable responsive layout/components, toast/status messaging, and lightweight CSS motion. Unauthenticated visitors enter through `/login` or `/register`; all catalogue and operations pages require a signed-in account. Provide exactly two dedicated profile sign-ins: `/login` for User and `/admin-login` for Administrator; matching server endpoints enforce the stored role. Successful User access enters `/` (or the originally requested User page); Administrator access enters `/admin` (or the originally requested Admin-only operations page). Other page routes: `/movies`, `/shows`, `/content/:id`, `/watchlist`, `/favourites`, `/admin`, `/admin/catalogue`, `/admin/submissions`, `/theatres`, `/theatres/:theatreId`, `/production`, and `/reports`, plus a not-found route. There is no Screen Manager sign-in or redirect. Route guards are a usability layer only; Express enforces permissions.

Catalogue data includes at least Interstellar, Spider-Man, Hulk, Iron Man, Doctor Doom (clearly identified as fictional demonstration content), Ok Kanmani, Hi Nanna, Avengers: Endgame, Dune, Avatar, The Lord of the Rings, and Baahubali, plus featured series. Bundle correctly matched poster images for the 11 real films under `frontend/public/posters/` and use stable `/posters/...` references in both catalogues; expose source-page attribution on detail views. Movie poster sources do not grant reuse permission; document ownership and unresolved rights. Keep Doctor Doom and Kingdom of Ash explicitly sample-only and clearly labeled as non-official concept art; the original Doctor Doom image generation is pending, so its temporary placeholder must not be presented as a completed poster. The atmospheric hero image is bundled locally as `frontend/public/afterglow-hero.webp`.

Seed at least 10 fictional theatres with the exact requested names, fictional locations/statistics and at least three screens each (30+). Administrator-only theatre details provide screen selectors and date/screen/content/status-filtered daily schedules. Provide schedules with multiple time slots and distinct completed, now-playing, upcoming/starting-soon, open gaps and maintenance cases, without valid overlaps. Derive screening status from selected date/time, start, end, maintenance and current time; never store stale display labels as authoritative. End time is content duration plus start time. A shared validator rejects missing fields, invalid duration, overlap, maintenance and outside-hours slots; a deterministic attempted conflict is demonstrated as a rejected simulation, not inserted as a valid schedule. Administrator production board supplies date navigation and day/week filters. Reports aggregate labelled demo/DB-backed schedules, theatre utilization, screenings by date, per-screen/per-title schedules, upcoming/completed and maintenance/conflict summaries.

The Administrator reviews Movie Submissions & Releases (poster, title, production company, release date and Pending Review/Approved/Rejected state) and can schedule only approved titles on existing operating screens. There are no production-company accounts and no Add Screen/Edit Screen controls. The User profile has no screen-management pages, controls, navigation or operational screening data. Administrator retains movie/show CRUD. No streaming, ticket booking, seat booking, payments, subscriptions or copyright/licensing management.

## Design system

- **Design Movement:** Cinematic dark-fantasy exhibition, fusing a premium genre-streaming catalogue with the glowing instrumentation of an imagined starship control room.
- **Core Principles:** (1) Poster-led storytelling and generous cinematic negative space; (2) orange is reserved for focus, selected state, urgency and action; (3) operational information remains dense but scannable through strong hierarchy; (4) every role-specific operation is legible and deliberate, never a decorative dead end.
- **Color Philosophy:** Near-black `#050505` and `#101010` create a dark screening-room foundation; warm orange `#FF7A00` and amber `#FF9D00` signal discovery, energy and active production; muted grey and restrained off-white preserve legibility. Borders are charcoal with occasional amber light. No blue or purple dashboard theme.
- **Layout Paradigm:** An editorial, horizontally unfolding cinematic experience: a wide asymmetrical hero above edge-aligned poster rails; operational pages use a compact left navigation rail and full-width timeline/table workspace; theatre detail nests an identity band, screen selector and schedule. On small screens, navigation collapses to a compact drawer and schedule rows become horizontally scrollable, not squeezed into unreadable cards.
- **Signature Elements:** A thin amber horizon/film-burn rule marking active sections; star-map pinpoints and fine radial nebula texture used sparingly; a bespoke eclipse-reel logo symbol combining a film aperture and orbit ring.
- **Interaction Philosophy:** Hover/focus reveals useful metadata and explicit actions; selection uses a persistent orange indicator; cards navigate to real detail pages; save actions give immediate state feedback and announce demo-vs-database persistence. Forms explain validation and schedule conflicts in context. Keyboard focus remains visible.
- **Animation:** Subtle 180–260 ms fades, border glow and small poster lift; a slow, low-opacity starfield drift only behind the home hero; respect `prefers-reduced-motion`; no autoplay video or heavy particle simulation. Route transitions must not delay interaction.
- **Typography System:** Use `Bebas Neue` for cinematic display titles with generous tracking, and `DM Sans` for UI, forms and operational tables; a system sans-serif fallback keeps the interface resilient. Display hierarchy: 56–72 px hero on desktop, 32–42 px page titles, 22–28 px section titles; dense schedule labels 12–14 px with tabular numerals and adequate contrast.
- **Brand Essence:** “A command deck for discovering cinematic worlds and orchestrating where they screen.” Personality: **cinematic, precise, exploratory**.
- **Brand Voice:** Headlines are evocative but concise; actions use direct verbs; operational feedback states outcomes plainly. Examples: “The next world is already in orbit.” and “That time slot overlaps Screen 02’s existing run.”
- **Wordmark & Logo:** A custom eclipse-reel mark: a circular aperture with a warm crescent/orbit crossing the film-reel center; pair with the uppercase wordmark `AFTERGLOW` in a condensed display face. The project title remains “Movie & Show Management System” in documentation.
- **Signature Brand Color:** Afterglow Ember `#FF7A00`, used as a strong accent rather than a page wash.

## Production deployment architecture

- The normal Preview/local launcher remains unchanged: Vite serves `5173` (Preview may supply `PORT=3000`) and the Express API serves `5000` through the same-origin `/api` proxy.
- The container build uses the pinned npm workspace lockfile, compiles `frontend/dist`, prunes development-only packages, and copies only production sources/artifacts into a Node 22 runtime image. The runtime entrypoint is `backend/src/server.js`.
- Production Express honors `PORT` (default `3000`) and binds `0.0.0.0`; it serves the hashed frontend bundle, `/manus-routes.json`, and extensionless React routes from `frontend/dist`, while retaining JSON behavior under `/api` and returning unauthenticated health at `/api/health`.
- Production startup fails closed unless `MONGODB_URI` and `JWT_SECRET` are supplied to the production runtime and `DEMO_MODE=false`; protected values are collected in WebDev's Production-only secret input and are never copied from Development, `.env`, client bundles, Docker build arguments or source files. The Docker build does not require the database to build, and its image never contains `.env` or private values.
